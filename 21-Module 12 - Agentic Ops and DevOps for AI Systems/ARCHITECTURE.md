# Module 12 Lab: Agentic Ops and DevOps for AI Systems

## Objective

This lab demonstrates an Agentic Ops workflow using a single notebook.

The lab fulfills these objectives:

- Create a CI/CD workflow for an AI application.
- Version and manage AI prompts using GitHub.
- Build an automated deployment pipeline for AI agents.

The business problem is AI support-assistant release management. A support operations team wants to update an AI assistant prompt safely, test the agent behavior, validate prompt files, and push the release assets to GitHub so GitHub Actions can verify the change.

## Prompt Versioning Design

The notebook creates three prompt versions:

| Version | Purpose |
|---|---|
| `1.0.0` | Initial support classification and next action |
| `1.1.0` | Adds severity and escalation guidance |
| `1.2.0` | Adds DevOps/change-risk and rollback thinking |

Learners can manually select a prompt version in the notebook:

```python
SELECTED_PROMPT_VERSION = "1.2.0"
```

This shows how one AI agent can behave differently when the prompt version changes.

## GitHub Actions Role

GitHub Actions does not host the AI agent.

In this lab, GitHub Actions works as the CI/CD validation layer:

```text
Prompt files pushed to GitHub
   |
   v
GitHub Actions starts
   |
   v
Checks prompt manifest
   |
   v
Checks prompt version files
   |
   v
Checks deployment manifest
   |
   v
Workflow passes or fails
```

This teaches learners that Agentic Ops is not only about writing agent code. It is also about controlling prompt changes, reviewing deployment metadata, and validating releases.

## GitHub Credentials Required

For the optional GitHub demo, learners need:

| Credential | Required For |
|---|---|
| GitHub repository URL | Cloning and pushing the demo branch |
| GitHub username/email | Creating a Git commit |
| GitHub Personal Access Token | Authenticating the push |

Recommended GitHub token scopes:

```text
repo
workflow
```

Do not store a GitHub token in committed code, markdown, or notebook output. The notebook uses `getpass` so the token is typed securely at runtime.

## How To Add GitHub Access Token

Use these steps when running the optional GitHub push section in the notebook.

1. Open GitHub in the browser.

2. Go to:

```text
Settings -> Developer settings -> Personal access tokens -> Tokens (classic)
```

3. Click:

```text
Generate new token -> Generate new token (classic)
```

4. Add a token name, for example:

```text
agentic-ops-lab-token
```

5. Select an expiry date that matches the training duration.

6. Select these scopes:

| Scope | Why It Is Needed |
|---|---|
| `repo` | Allows the notebook to clone, create a branch, commit, and push to the repository. |
| `workflow` | Allows the notebook to add or update files inside `.github/workflows/`. |

7. Click:

```text
Generate token
```

8. Copy the token immediately. GitHub will not show it again.

9. In the notebook GitHub configuration cell, paste the token only when this line asks for it:

```python
GITHUB_TOKEN = getpass("GitHub token: ")
```

10. After the demo, delete or rotate the token from GitHub if it was created only for training.

Do not paste the token directly into notebook code. Do not commit the token to GitHub.

## Key Learning Points

- Prompt files should be versioned like source code.
- Prompt changes can be validated before deployment.
- GitHub Actions can act as a CI/CD quality gate for AI assets.
- Deployment metadata helps teams audit which prompt version is released.
- A notebook can demonstrate the full Agentic Ops lifecycle in a guided training format.
